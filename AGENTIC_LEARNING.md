## 2. Advanced Agentic Experience (AX) Paradigms
The shift from 2024 to 2025 moves AI from "Assistant" to **"Teammate."**

### Collaboration Patterns
- **ReAct & Co-Creation Loops**: Every task starts with reasoning, followed by iterative cycles where the agent generates options and the user provides refinement or critique.
- **Shared Autonomy Controls**: Implement clear boundaries for agent actions:
    - **Watch Mode**: User observes agent actions in real-time.
    - **Assist Mode**: Agent suggests next steps for user approval.
    - **Autonomous Mode**: Agent executes complex, multi-step tasks independently with a final audit checkpoint.
- **Dynamic Task Allocation**: Tasks are divided based on strengths: AI handles heavy math, parsing, and data-density; humans handle subjective design and ethical alignment.

### Trust Signals & Legibility
- **Legible Reasoning Paths**: Always show the "why" and "how" (e.g., "Calculating Flood Q using HSS Nakayasu per SNI 2415:2016...").
- **Confidence Scoring**: Provide transparency on AI-generated recommendations (e.g., "95% confidence in watershed boundary").
- **Audit Trails & Trajectory Logging**: Maintain a clear record of every decision and action taken, allowing for "Goal-Action Trace Logging."

## 3. LLM-Native & Engineering UI Principles
Engineering workstations require a specific focus on precision and data-density.

- **Flattened GovTech Aesthetic**: Strictly `shadow-none`. Use `#e2e8f0` (slate-200) borders. Modern UI should be high-contrast and sharp-bordered.
- **PUPR Color Palette**: 
    - **Navy (#0c3a66)**: Command, navigation, and primary hierarchy.
    - **Yellow (#f2c114)**: Critical highlights, state changes, and PUPR branding.
- **Tabular Precision**: Mandatory `tabular-nums tracking-tight` for all numerical data to ensure scan-ability and vertical auditability.
- **Accessibility (WCAG 2.1 AA)**: Focus-visible rings, descriptive aria-labels, and high-contrast text (minimum 4.5:1).

## 4. Technical Reliability & Error Transparency
Agentic systems must be resilient and self-correcting.

### Reliability Architecture
- **Graceful Degradation**: Implement fallback options and "circuit breakers" for AI-powered features.
- **Preventing Drift**: Use prompt version control and versioned state schemas to avoid performance degradation over time.
- **Worker-First Processing**: Offload complex hydrology engines (n² algorithms) to Web Workers to keep the UI responsive.

### Error Transparency
- **Trajectory-Level Explainability**: Diagnose failures within a sequence of actions rather than just single-step errors.
- **Human-in-the-Loop (HITL)**: Mandatory checkpoints for high-risk numerical changes or data commits to Supabase.
